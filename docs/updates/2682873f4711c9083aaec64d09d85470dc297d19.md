# OpenBot coding-agent workflow alignment

## Intent of the change

- Make coding agents follow current provider, agent, Computer, deployment, ADR, and fork-update rules.
- Add one agent-authoring workflow for Eve-shaped agent folders.
- Make PR creation block on stale package docs, misplaced provider contracts, missing ADR review, or missing fork update record.
- Keep runtime agent skills separate from repository coding-agent skills.

## Architecture changes

- No runtime architecture changes.
- Coding workflow now routes edits through owning skills and durable records.
- Provider contracts must live in owning package `src/core.ts` or `src/core/index.ts`.
- Agent source must live under `configuration/agents/<id>/`.
- Every repository-changing upstream PR must end with one hash-addressed update note commit.

```mermaid
flowchart LR
  E["Repository edit"] --> S["Owning coding-agent skill"]
  S --> V["Focused validation"]
  V --> A["Architecture and ADR review"]
  A --> I["Implementation commit"]
  I --> U["docs/updates implementation-hash.md"]
  U --> P["Draft pull request"]
```

## Summarized package changes

- `.agents/skills/create-or-update-agent`: new agent authoring workflow. Covers fixed agent layout, Zod tools, typed Computer calls, instrumentation, instructions, private workspace seeds, and `openbot new-agent`.
- `.agents/skills/create-pr`: enforces package README public API checks, provider core placement, ADR review, and the two-commit fork update record protocol.
- `.agents/skills/implement-provider`: documents provider-local core contracts, Handlebars assets, optional build/deploy lifecycle, prompt/tool hooks, and focused adapter tests.
- `.agents/skills/add-api-endpoint`: aligns RPC ownership and typed Computer service rules.
- `.agents/skills/run-openbot`: aligns blank-fork init, dev/local/Vercel ownership, separate desktop/control service, and deployment checks.
- `.agents/skills/grill-with-docs`: requires concise ADRs, useful Mermaid diagrams, and append-only timestamped updates.
- Other affected workflow skills now use current package names, configuration paths, and deployment commands.
- `AGENTS.md`: clarifies shared Computer workspace seeding while preserving explicit typed per-agent Computer tools.
- No published package API, runtime configuration, secret format, or deployment artifact changed.

## Critical to apply to forks

yes

- Fork coding-agent instructions should take these changes. Otherwise future automated edits may recreate removed core packages, stale provider factories, global skills/sandbox folders, or unsupported deployment flows.
- Copy or merge the `.agents/skills/` and `AGENTS.md` changes while preserving fork-specific coding instructions.
- Ensure custom provider interfaces remain in their owning provider package `core.ts` or `core/index.ts`.
- Ensure custom agents remain under `configuration/agents/<id>/` and Computer tools bind the fixed agent ID.
- For every later upstream merge, require the matching `docs/updates/<implementation-commit>.md`, review critical actions, and write fork-local notes under `configuration/docs/update-notes/`.
- Validate changed skills with their `quick_validate.py` scripts and run `git diff --check`.
